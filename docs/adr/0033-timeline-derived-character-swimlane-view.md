# Timeline — derived character-swimlane view

**Status**: partially superseded by ADR-0034. The **UI surface** below (character-swimlane visualization with a packed node belt, radial spokes, custom SVG + d3-zoom, and the visual absorption rule) was abandoned after three failed implementation attempts — see ADR-0034 for the replacement (uniform character-swimlane grid, non-proportional, no absorption). The **agent surface** (the `timeline_lookup` tool: flat time-ordered list, no absorption, chronological truth) remains accurate and unchanged.

A World's only entities carrying in-world time are Event and Scene (`startAt` / `endAt`, ISO 8601); Characters, Locations, Items, Lore, Chapters, and Novels have no time field. We introduce a **Timeline**: a derived, read-only chronological projection of a World's Events and Scenes — never persisted, never authored, with no dedicated table or entity. It is computed at render time and exposed through two surfaces that share the same data origin but intentionally diverge in projection.

The **UI surface** renders a character-swimlane visualization: the Y axis is Characters (each a horizontal lane), the X axis is time, and Event/Scene nodes span the lanes of their `characterRefs`. Nodes are time-interval bars (`startAt`→`endAt`) living in a dedicated, greedily-packed node belt above the lanes; thin **spokes** radiate from each node down to the lanes of its participants, so a node's footprint stays decoupled from its participant count — a "convergence" reading without distorting the lanes. A **visual absorption rule** applies on this surface: an Event referenced by a Scene's `eventIds` is not drawn bare but absorbed into that Scene's node, so the UI optimizes for visual de-duplication. The default lane set is Characters with participation-reference count > 2 (user-configurable). Elements without `startAt` are excluded from the canvas (a badge reports the hidden count); nodes without `characterRefs` sit in muted bottom rows of the node belt. Zoom is **semantic time-granularity**: it shifts the `scaleTime` domain and re-derives tick granularity (millennia → … → hours), not a CSS scale.

The **Agent surface** is the `timeline_lookup` tool (`consentLevel: "auto"`). It returns a flat, time-ordered list of Event and Scene entries — each carrying id, name, startAt, endAt, resolved location name, participant names, a description excerpt, and cross-reference annotations (`narratedBySceneNames` for Events, `narratedEventNames` for Scenes) — filterable by character, location, time window, novel, and limit, served by a single Rust aggregation command. Crucially, the tool **does not apply the UI's absorption rule**: every Event and Scene appears at its own `startAt`, because chronological truth matters more to the model than visual de-duplication. This intentional divergence between the two projections is the single most surprising property of the design and must not be "unified."

The visualization is built on **custom SVG + d3-zoom**, not a graph library. The swimlane structure (static lane backgrounds, packed node belt, radiating spokes) maps to SVG primitives directly, whereas a graph library's node/edge model would impose overhead — notably requiring an invisible anchor node per spoke endpoint and hand-computed lane backgrounds. Off-the-shelf timeline libraries were surveyed (vis-timeline, react-chrono, frappe-gantt, markwhen, xyflow): each is either unmaintained, wrong-paradigm (slideshow rather than pan/zoom axis), or fights the swimlane/spoke structure; none fit, so the bespoke SVG path was taken.

Considered and rejected: an **authored/curated timeline** as a new entity (overlaps Event, introduces sync hazards — rejected for redundancy); **entity-type tracks** instead of character swimlanes (loses the convergence semantic the design is built around); **xyflow / React Flow** as carrier (its node/edge model fights lanes and spokes — reversed despite being the generic-timeline recommendation); **bending-lane "storyline" layout** (research-grade layout algorithms, no production library, clutter at scale); **pan/zoom-as-filter** for the time range (loses explicit windowing, disorienting at millennial spans — a brushable overview strip is used instead).

Consequences: the UI and tool projections diverge by design — a future change to absorption must be made separately per surface, not globally. The custom SVG visualization is a maintenance commitment (pan/zoom, row packing, spoke routing, accessibility all owned in-repo) accepted in exchange for a faithful fit to the swimlane model that no off-the-shelf library provides. Filtering (character lanes, entity-type toggle, related Location/Item, time-range brush) is the primary interaction on the UI surface; the tool mirrors the same filter dimensions in its input schema.
