# TimeMapper — user-authored JS, output-only, Web Worker isolation

**Status**: accepted.

Fictional worlds use idiosyncratic time systems (named eras, non-Gregorian calendars, seasonal reckonings) that don't fit database storage. We keep `Event.startAt` / `Scene.startAt` as ISO 8601 strings — the immutable truth — and introduce a per-World **TimeMapper**: a user-authored JavaScript function `(iso: string) => string` that renders ISO timestamps into the World's custom time representation at display time. The mapper is strictly output-only: it never parses user input, never affects storage, and never participates in the data model. Input remains ISO; the mapper is a pure display-layer rendering function.

Chosen over two alternatives considered. A **custom mini-language** (bounded grammar of arithmetic + lookup + formatting primitives) was rejected because the authoring cost falls on the user either way, and users (or their external AI assistants) already know JavaScript — a new grammar adds learning friction without unlocking anything JS can't express. **Bidirectional mapping** (parse world-time strings back to ISO) was rejected because fictional time is deliberately vague ("early spring of the Bloom Moon") — forcing precise parsing destroys the stylistic ambiguity authors intend, and a parser lenient enough to accept everything parses nothing.

The function executes in an isolated **Web Worker** via native browser primitives — `new Blob([code], { type: "text/javascript" })` + dynamic `import(url)` — with no transpiler dependency. Browsers cannot run TypeScript natively; adding Sucrase/esbuild-wasm would introduce the "compilation system" we explicitly avoid. A 50ms watchdog terminates the worker on infinite loops. Broken code silently falls back to displaying raw ISO in the UI (with WARN/ERROR logs per ADR-0014), but surfaces as a non-fatal `tool-error` to the agent via the `format_time` tool (mirroring the `ToolDeniedError` pattern from ADR-0025) so the model can adapt its prose. The agent never writes mapper code — authoring is a human activity assisted by external AI tools (ChatGPT, Claude web); the agent is strictly a consumer with a single `format_time` tool.

The mapper source lives in a new `world_config` KV table inside each World's `world.db` (mirroring the `space_config` pattern from ADR-0007), key `time_mapper`, value `{ code: string }`. The existing `<input type="datetime-local">` in Event/Scene forms is retained — input stays Gregorian/ISO — but gains a `<TimePreview>` component beside the picker showing the mapped world-time string, so users see the correspondence without leaving the form. All display surfaces (cards, lists, agent responses) route timestamps through the mapper; on failure they fall back to raw ISO.
